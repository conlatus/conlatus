# Asynchronous Database Abstraction Layer (SQLAlchemy 2.0 & Alembic)

## Overview
The Conlatus platform database layer is built using **SQLAlchemy 2.0 (Async)** and **Alembic**. It provides a dialect-agnostic abstraction layer that runs seamlessly on local **SQLite** (`conlatus.db`) with zero manual setup, while instantly scaling to production **PostgreSQL** providers (**Supabase**, **Neon**) via environment variables.

## Key Features & Technical Specifications

### 1. Dialect-Agnostic Driver Mapping
The engine automatically detects the `DATABASE_URL` format and maps it to appropriate drivers:
- **Async Engine:**
  - `sqlite://` or `sqlite+aiosqlite://` -> Uses `aiosqlite` driver with `check_same_thread=False` and automatic WAL mode (`PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON;`).
  - `postgres://` or `postgresql://` -> Maps to `postgresql+asyncpg://` with connection pooling (`pool_size=10`, `max_overflow=20`, `pool_pre_ping=True`).
- **Sync Engine (Alembic):**
  - Converts `sqlite+aiosqlite://` -> `sqlite://`
  - Converts `postgresql+asyncpg://` -> `postgresql://`

### 2. Standardized Base Mixins
- **`UUIDMixin`**: Enforces UUID v4 primary keys across all models, stored as native UUIDs in Postgres and binary/string UUIDs in SQLite.
- **`TimestampMixin`**: Automatically maintains timezone-aware `created_at` and `updated_at` timestamps using server-side defaults (`func.now()`).

### 3. Core Database Models
1. **`companies`**: Organization metadata (`id`, `name`, `domain`).
2. **`users`**: Admin & Recruiter user accounts (`id`, `company_id`, `email`, `full_name`, `hashed_password`, `role`, `is_active`).
3. **`roles`**: Job roles, competency definitions, and rubric JSON (`id`, `company_id`, `title`, `description`, `competencies`, `rubric`).
4. **`questions`**: Curated & LLM-generated questions (`id`, `role_id`, `content`, `category`, `difficulty`, `ideal_answer`, `rubric_criteria`, `is_curated`).
5. **`interviews`**: Candidate interview instances (`id`, `role_id`, `user_id`, `candidate_name`, `candidate_email`, `token`, `status`, `started_at`, `completed_at`, `expires_at`).
6. **`transcripts`**: Real-time turn-by-turn dialogue logs (`id`, `interview_id`, `speaker`, `message`, `timestamp`, `audio_url`, `metadata_json`).
7. **`reports`**: Scored evaluation reports & human recruiter decisions (`id`, `interview_id`, `overall_score`, `recommendation`, `rubric_breakdown`, `summary`, `human_decision`, `human_notes`).

## FastAPI Dependency Usage

Inject the database session into any FastAPI router using `get_db`:

```python
from fastapi import APIRouter, Depends
from sqlalchemy.ext.asyncio import AsyncSession
from core.database import get_db

router = APIRouter()

@router.get("/items")
async def list_items(db: AsyncSession = Depends(get_db)):
    # DB session automatically handles commit/rollback/close
    ...
```

## Alembic Migration Commands

To apply database migrations:
```bash
# Run migrations from backend/ directory
python -m alembic upgrade head

# Generate a new migration revision after model changes
python -m alembic revision --autogenerate -m "Describe migration"
```
